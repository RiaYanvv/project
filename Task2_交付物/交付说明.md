## 三、评分口径（写入 `Rubric` sheet）

- **Relevance 0/1/2**：2 = 直接回答该题的信息需求；1 = 同风险域、可作支撑上下文；0 = 无关。
- **Authority 0/1/2**：由来源等级确定性映射 —— S / A+ / A = 2，B+ = 1。
- **Coverage 0/1/2**：Top-5 合起来是否覆盖该题的全部关键面向。

## 六、语料与案例的 held-out 设计（重要）

**结论：Task 5 的 17 个企业案例是评测答案键，不进入 RAG 语料。**

- 语料 = **30 篇**（全部为 Task 1 的政策 / 宏观 / 贸易 / 企业公开报道证据），DB 为 30 documents / 2,872 chunks。
- 案例文档已从 `data/raw/case/` 迁出到 `data/evaluation/case_benchmark/case/*.md`，`ingest_dataset.py` 不再扫描该路径；
  registry `metadata/evidence_metadata_v0.1.json` 同步重建为 30 条（无任何 `RELOC_*` / `PLUS1_*` / `RETURN_*`）。
- 结构化案例库保留在 `data/evaluation/case_benchmark/evidence_cases_v0.1.xlsx` 与 `data/processed/case_database_v0.1.xlsx`。

**为什么必须摘出来**：案例一旦入库，案例题检索会直接把案例文档本身（即答案键）捞回 Top-5，
Recall / 风险召回虚高，评测失去意义。

**实测影响（摘出前后同一脚本对比）**：

| Task 3 Recall@10 | 0.810 | **0.893** |
| Task 3 Entity Accuracy | 0.929 | **0.885** |
| Task 6 Risk Recall（基线） | 0.461 | **0.779** |
